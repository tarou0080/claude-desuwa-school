# なぜこれで挙動が変わるのか

このリポジトリのルールは、思いつきの寄せ集めではありません。**すべて Claude Code の既定の振る舞いを打ち消すために存在します。**

モデルが新しくなれば既定も変わります。既定が賢くなればルールは不要になり、既定が変わればルールは効かなくなります。そのとき何を見直せばいいか分かるように、「何を打ち消しているか」をここに一覧します。

---

## 1. 既定では、サブエージェントを起動しない

Claude Code のシステム側の指示には「**ユーザーが明示的に頼まない限りサブエージェントを起動するな**」という趣旨のルールが入っています。起動はコールドスタートで、同じ資料を読み直すぶん高くつくためです。素のモデルが委譲しないのは不具合ではなく、設計どおりの挙動です。

**打ち消し方**: `CLAUDE.md` の振り分け表で「この性質の作業は委譲する」と明示し、`~/.claude/agents/` に委譲先を用意する。

**なぜ委譲先の定義が要るか**: 定義が無いと汎用エージェントしか選べません。汎用エージェントは何の制約も持たないので、生ログを丸ごと読んで丸ごと返してきます。それでは節約になりません。investigator に「読み取り専用・結論先行・生ログ貼り付け禁止」と書いてあることが、節約の実体です。

**打ち消しすぎないための歯止め**: 振り分け表の「委譲しない」2 行。これが無いと、5 分で終わる作業まで委譲して逆に高くつきます。

---

## 2. 既定では、十分な情報が揃った時点で実装を始める

Claude Code は「情報が揃ったら行動せよ、既に決まったことを蒸し返すな」と指示されています。日常的な判断でいちいち止まらないための、まっとうな設計です。

副作用として、**要件の解釈がズレていても、そのまま完成品まで作ってしまいます**。ズレが発覚するのはコードが出来上がった後です。

**打ち消し方**: 「実装前に設計提示→承認を得てから着手」。ズレたときに捨てるのが、コードではなく設計の文章になります。

**提示内容を規定している理由**: 「何のファイルに何を書くか」を並べられても承認判断はできません。判断に必要なのは、責務の分割・既存動作への影響・そして **操作後に自分が体験する挙動** です。だから CLAUDE.md でそこまで含めるよう指定しています。

---

## 3. 既定では、手元の文脈だけで答える

モデルは会話とコードから読み取れることで答えます。過去の経緯・却下した案・ハマった罠は、どこにも書いていなければ存在しないのと同じです。

「うちの Claude は要件をよく分かっている」と感じるとき、それはモデルの記憶力ではなく、**過去の要件が文書化されていて毎回読み直されている** だけです。

**打ち消し方**: 「回答・作業着手前に設計ドキュメントを無条件で grep」。判断の余地を残すと読まなくなるので、条件を付けずに書いてあります。

**書く内容を限定している理由**: 構造や実装手順を書いてもコードを読めば分かるので効果がありません。効くのは「なぜこの設計を選んだか」「何を捨てたか」「既知の罠」です。

---

## 4. サブエージェントは会話の文脈を引き継がない

新しく起動したサブエージェントは、それまでのやり取りを一切知りません。「さっきの件、続きをお願い」は通じません。

**打ち消し方**: 「委譲指示は自己完結させる（背景・対象パス・完了条件・検証方法を含める）」。

---

## 5. サブエージェントの報告は、検証されていない

サブエージェントは間違えます。断定的な口調で間違えることもあります。

**打ち消し方**: 「成果物はメインセッションで検証してから完了報告する」。委譲は責任の移譲ではありません。

---

## 6. 既定では、やったことをコードで説明する

技術的に正確な報告ですが、承認する側が知りたいのは「自分の画面と操作がどう変わるか」です。

**打ち消し方**: 「コードの説明をしない — どのようなユーザ体験になるかを報告する」。

---

## 7. 既定では、自分の権限を推測で判断する

「この認証情報ではできなさそうだ」と判断すると、モデルは試さずにユーザーへ作業を投げ返します。壊さないための安全側の振る舞いですが、**読み取り系のAPIを1回叩けば済む確認を省いて、人間に手作業をさせる**という形で裏目に出ます。

判断材料が変数名・コメント・過去のドキュメントだけだと、特に外します。それらは書かれた時点の用途を表しているだけで、現在の実際の権限とは無関係です。

**打ち消し方**: 「ユーザーに手作業を依頼する前に、自分で実行できないことを実測で確認する」。

依頼する前に一度試す。それだけで、相手の手を止める回数が変わります。

## 設定の探索順（どこに置くと効くか）

| 置き場所 | 効く範囲 | 共有 |
|---|---|---|
| `~/.claude/CLAUDE.md` | 全プロジェクト | 個人のみ |
| `<リポジトリ>/CLAUDE.md` | そのリポジトリ | コミットすればチーム全体 |
| `~/.claude/agents/*.md` | 全プロジェクト | 個人のみ |
| `<リポジトリ>/.claude/agents/*.md` | そのリポジトリ | コミットすればチーム全体 |

両方にある場合、プロジェクト側が優先されます。「設定を入れたのに効かない」ときは、まずリポジトリ側に別の `CLAUDE.md` が無いか確認してください。

---

## メンテナンスの方針

新しいモデルが出たら、このリストと実際の挙動を突き合わせてください。

- **既定が賢くなっていたら、そのルールを削る** — ルールは無料ではありません。毎ターン読まれ、毎ターン課金され、多すぎれば互いに薄まります
- **既定が変わってルールが効かなくなったら、書き方を変える** — 効いていないルールを放置するのが一番たちが悪い

足すより削るほうが効きます。
