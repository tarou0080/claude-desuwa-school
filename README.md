# claude-desuwa-school

**Claude お嬢様学校** — Claude Code に行儀作法を仕込むための設定一式ですわ。

以降は真面目な話です。

素の Claude Code は非常に有能ですが、放っておくと **何でも自分でやります**。長いログも自分で読み、コードも自分で全部抱え、要件を推測したままいきなり実装します。悪いことではありませんが、従量課金の環境ではこれが直接コストになり、認識のズレは実装が終わってから発覚します。

このリポジトリは、その既定の振る舞いを 3 点だけ上書きします。

1. **人に任せる** — 長い調査・機械的な生成をサブエージェントへ委譲し、要約だけ受け取る
2. **先に伺いを立てる** — 実装前に設計を提示して承認を得る
3. **家の事情を覚えておく** — 設計ドキュメントを読んでから作業し、決まったことを書き残す

同じモデルでも、この 3 つがあるかないかで挙動はまるで変わります。モデルを変える必要はありません。

---

## 導入

ファイルを 3 種類コピーするだけです。ビルドもインストーラもありません。

```
このリポジトリ                →  コピー先
------------------------------------------------------------
CLAUDE.md                     →  ~/.claude/CLAUDE.md
agents/*.md                   →  ~/.claude/agents/
settings.example.json         →  ~/.claude/settings.json （任意）
docs/design-doc-template.md   →  好きな場所（設計ドキュメントの雛形）
```

`~/.claude/` 配下に置くと **全プロジェクトで有効** になります。VSCode 拡張でどのリポジトリを開いても効きます。リポジトリ単位で効かせたい場合は、代わりに `<リポジトリ>/CLAUDE.md` と `<リポジトリ>/.claude/agents/` に置いてください（そちらはコミットされるのでチームに共有されます）。

コピー後に 1 箇所だけ書き換えます。`CLAUDE.md` 内の `{{docs/design/}}` を、あなたが設計ドキュメントを置くパスに変えてください。まだ 1 本も無くても構いません（無い場合はそのまま進むようにルールを書いてあります）。

反映されているかは、Claude Code を起動して `/agents` を叩けば確認できます。scribe / investigator / implementer が並んでいれば成功です。

> **既存の `~/.claude/CLAUDE.md` がある場合は上書きしないでください。** 中身をマージするか、いったん退避してから置いてください。

## 導入後、何が変わるか

**調査を頼んだとき**
「このエラーの原因を調べて」と頼むと、Claude 自身がログを読み込む代わりに investigator を起動します。生ログはサブエージェント側で消費され、メインの会話には結論と根拠（ファイル名:行番号）だけが返ります。以降のやり取りで生ログが再課金され続けることがなくなります。

**実装を頼んだとき**
いきなりコードが出てきません。先に「責務をどう分けるか」「既存の動作に何が起きるか」「変更後にあなたの画面がどう変わるか」が提示され、そこで止まります。承認すると implementer が実装します。ズレていた場合、手戻りするのは設計の文章だけです。

**定型作業を頼んだとき**
テストデータの大量生成、フォーマット変換、grep 結果の集計といった判断の要らない作業は scribe（Haiku）に流れます。

**作業が終わったとき**
決まった設計・ハマった罠を、頼まなくても設計ドキュメントに書き足す提案が出ます。次回、同じ話を最初から説明する必要がなくなります。

## 誰に何を任せるか

この振り分け表が本体です。これが無いと「とりあえず全部 Sonnet」になり、節約になりません。

| 作業の性質 | 委譲先 | モデル |
|---|---|---|
| 判断ゼロ・出力が長い・検証が軽い | scribe | Haiku |
| 原因究明・複数ファイルの読解が要る調査 | investigator | Sonnet |
| 承認済み設計の実装 | implementer | Sonnet |
| 設計判断・要件解釈・セキュリティ | **委譲しない** | メインセッション |
| 数分で終わる小タスク | **委譲しない** | メインセッション |

最下段の 2 行を消さないでください。

委譲は万能ではありません。サブエージェントは毎回コールドスタートで、同じ資料を読み直します。5 分で終わる作業を投げると、起動コストのほうが高くつきます。判断が要るものを Haiku に落とせば、やり直しで倍払うことになります。**得をするのは「読む量が多く、返す量が少ない」作業だけ**です。

## 効果が出ない場合

- **Claude Code 本体が古い** — `claude --version` で確認し、`claude update`。VSCode 拡張は本体 CLI を呼んでいるので、拡張のバージョンを見ても意味がありません
- **`/agents` に出てこない** — 置き場所が `~/.claude/agents/` か、frontmatter の `---` が壊れていないか
- **委譲してくれない** — 頼んだ作業がそもそも短い可能性があります。それは正常な判断です
- **設計提示なしで実装が始まる** — プロジェクト側の `CLAUDE.md` が優先されて上書きされていないか確認してください

## メンテナンスについて

ここに書いてあるルールは、すべて **Claude Code の既定の振る舞いを打ち消すため** に存在します。何を打ち消しているかは [docs/why.md](docs/why.md) に一覧してあります。

モデルが新しくなると既定も変わります。既定のほうが賢くなればルールは不要になり、既定が変わればルールは効かなくなります。挙動がおかしくなったら、まず why.md の一覧と実際の挙動を突き合わせてください。ルールを足すより、要らなくなったルールを削るほうが効きます。
